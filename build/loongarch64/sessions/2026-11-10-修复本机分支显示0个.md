## 1. 现象

侧边栏分支树中 **「本机分支 / LOCAL BRANCHES」分组为空**，计数为 `0`；
远程分支、标签同样受影响。运行环境为 Loongnix **loongarch64** 本机构建（`out/linux-loongarch64/`）。

计数逻辑在 `src/ViewModels/Repository.cs`：按 `b.IsLocal && !b.IsDetachedHead`
统计 `Commands.QueryBranches` 的结果。

## 2. 排查过程：前几次都猜错了方向

**一开始完全没往 Git 版本上想**，排查过程如下：

1. **先怀疑自构建产物** —— 本机版是自拼的 .NET 10 SDK + JIT 发布，
   自然会怀疑是龙芯上的运行时 / 自编译 SDK 有问题（.NET、Avalonia、SkiaSharp 之类）。
2. **排除运行时** —— 应用能正常启动、界面正常渲染，只有分支树这一块是空的，
   不像是整体运行时崩坏。
3. **再怀疑仓库状态** —— 怀疑当前目录不是 Git 仓库、HEAD 游离、或者索引损坏；
   用命令行 `git status` / `git branch` 看仓库一切正常，但这些命令**不带 `--format`**。
4. **手工复现上游那条命令时才露馅** —— 把 `QueryBranches` 实际执行的
   `git branch -l --all -v --format="..."` 拿到终端里手敲，Git 直接报错：

   ```
   fatal: 未知的字段名：worktreepath
   ```

   这才第一次把方向转到 **Git 版本** 上：同一时刻 `git --version` 显示 **2.20.1**。

教训：带 `--format` 的原子查询与普通 `git branch` 行为差别很大；
排查「界面某块为空、命令行看着却正常」时，第一步就该把 UI 实际执行的那条命令抄出来手跑。

## 3. 根因

1. `src/Commands/QueryBranches.cs` 取分支用的是
   `git branch -l --all -v --format="%(refname)%00%(committerdate:unix)%00%(objectname)%00%(HEAD)%00%(upstream)%00%(upstream:trackshort)%00%(worktreepath)"`
   （注意是 `git branch --format`，**不是** `for-each-ref`）。
2. `%(worktreepath)` 原子需要 **Git 2.31**；同批原子中 `%(HEAD)`（2.13）、
   `%(upstream:trackshort)`（2.11）均可用，**只有这一项致命**。
   Git 2.20.1 遇到不认识的原子会让整条命令失败，而不是忽略该字段。
3. 失效链路：`ReadToEndAsync()` → `IsSuccess == false` → `GetResultAsync()`
   **静默返回空列表**（无任何错误提示）→ `LocalBranchesCount = 0`。
4. 同类问题：`git branch --show-current` 需要 **Git 2.22**
   （用于 `InProgressContexts` 的合并/变基检测、`WorkingCopy`），本机同样失败返空。
5. 版本对照：上游声明的最低 Git 版本是 `GitVersions.MINIMAL = 2.25.1`
   （`src/Models/GitVersions.cs`），本机 2.20.1 **本就在官方支持范围之外**；
   而上游实际用到的 `%(worktreepath)` 又需要 2.31 —— 上游的「声明版本 2.25.1」
   与「实际依赖 2.31」本身就没对齐（上游问题，非本机引入）。

## 4. 曾经的临时方案：改源码做兼容降级（已撤销）

会话当天先按「给旧 Git 做降级」实现了一版：

| 文件 | 当时的改动 |
| --- | --- |
| `src/Models/GitVersions.cs` | 新增常量 `WORKTREE_PATH = new(2, 31, 0)` |
| `src/Commands/QueryBranches.cs` | 拆分 `FORMAT_BASE` / `FORMAT_WORKTREE_PATH`，按 `Native.OS.GitVersion` 决定拼不拼该原子；失败时去掉该原子重试一次；旧 Git 路径下用 `git worktree list --porcelain` 回填 `WorktreePath`；`ParseLine` 字段数校验由 `!= 7` 放宽为 `!= 6 && != 7` |
| `src/Commands/QueryCurrentBranch.cs` | `--show-current` 失败时回退 `symbolic-ref --short HEAD`（所有版本都支持，HEAD 游离时同样返回空，与 `--show-current` 行为一致） |

**为什么撤销**：

- 上游支持范围是 Git ≥ 2.25.1，本机 2.20.1 属于「官方就不支持」的版本，
  为它改上游源码，等于给仓库长期背一个只服务于单机的分叉；
- 兼容层要覆盖的不止分支查询（`git restore` 2.23+、`stash push --pathspec-from-file` 2.25+、
  `merge-tree --write-tree` 2.38+、`git replay` 2.44+ …），补齐是一整套工作量；
- 真正的解法就一句话：**把 Git 装新**，源码一行都不用动。

**撤销方式**：三个文件恢复为上游版本（`git restore --source=HEAD --staged --worktree`），
仓库源码零改动；只有 `.gitignore` 新增 `out/` 一行予以保留（忽略本机构建输出目录）。

## 5. 最终方案（环境侧，未进仓库）

### 5.1 自装新版 Git

| 路径 | 版本 | 说明 |
| --- | --- | --- |
| `/home/m700s/.local/bin/git` | **2.56.1** | 2026-11-11 10:05 安装，自用版本，PATH 中优先于系统版本 |
| `/usr/bin/git` | 2.20.1 | Loongnix 自带，保持不动 |

系统 Git 2.20.1 原样保留，不与自装版本冲突（靠 PATH 顺序区分）。

### 5.2 配置 SourceGit 使用哪个 Git

- 偏好设置 → **「Git 安装路径」**（`src/Views/Preferences.axaml` 的 `GitInstallPath`）
  → 填 `/home/m700s/.local/bin/git`；
- 该值持久化在 `~/.config/SourceGit/preference.json`：

  ```json
  "GitInstallPath": "/home/m700s/.local/bin/git"
  ```

- 加载逻辑：`GitInstallPath` 的 setter 写入 `Native.OS.GitExecutable` 并触发
  `UpdateGitVersion()`（`src/Native/OS.cs`）；`PrepareGit()`
  （`src/ViewModels/Preferences.cs`）只在路径为空或文件不存在时才重新探测，
  **所以配置一旦写好就一直生效**，不依赖启动环境。

### 5.3 还有两道保险

- `src/Native/Linux.cs` 的 `FindExecutable("git")` 按 `PATH` 顺序逐个目录找；
  本机 PATH 中 `~/.local/bin` 排在 `/usr/bin` 之前 → 终端启动直接命中新版；
- PATH 里找不到 git 时，`FindExecutable` 还会兜底直接查 `~/.local/bin/git`。

因此桌面快捷方式 / 开机自启（那种 PATH 很干净的环境）也不会退回系统旧版。

### 5.4 验证结果（上游原样代码，未打任何兼容补丁）


命令退出码 0，`%(worktreepath)` 正常输出工作树路径，`--show-current` 也正常。

### 5.5 附带收益

`Native.OS.GitVersion` 现在探测到 **2.56.1**，上游各版本门槛全部满足：
`git restore`（2.23+）、`stash push --pathspec-from-file`（2.25+）、
`merge-tree --write-tree`（2.38+）、`git replay`（2.44+）等新特性都能用，
不必再逐项降级。

## 6. 遗留风险 / 后续建议

* **静默复现的可能**：若 `~/.config/SourceGit/preference.json` 被清空、
  或偏好里的 Git 路径被改回 `/usr/bin/git`，旧症状会**无声无息**地回来
  （上游失败时只返回空列表，不报错）。加固已于 2026-11-11 落地：
  启动器 `build/loongarch64/sourcegit-launch.sh` 现在会
  `export PATH="$HOME/.local/bin:$PATH"`，桌面 / 自启这种 PATH 很干净的环境
  也能命中 Git 2.56.1；此外 `preference.json` 的 `GitInstallPath` 是第二道保险。
* 上游把「声明最低版本 2.25.1」与「实际使用 `%(worktreepath)`（2.31）」混在一起，
  建议向上游反馈统一版本门槛（本机无需处理）。
* 同类静默失败还有：`git branch --format` 任何字段不被支持都会让整条命令失败，
  排查时以「手工跑 UI 实际执行的那条命令」为准。
* 环境副作用记录（保留存档）：`/tmp` 会被定期清理（临时工程需放在 `out/`）；
  曾误用 `pkill -f` 匹配到自身命令、并误批量最小化 175 个窗口（已恢复）。
