## 1. 现象

SourceGit 2026.24（Avalonia，发布目录 `out/linux-loongarch64`）在本机
loongarch64 / Loongnix 20 上启动后，点击「打开文件夹」
（欢迎页工具栏 → 「打开本地仓库」→ 弹窗内的文件夹按钮）→ 进程被 SIGABRT 直接杀掉。

stderr 关键行：

```
(Gtk-WARNING **: drawing failure for widget 'GtkLabel': error occurred in libfreetype
(Gtk-WARNING **: drawing failure for widget 'GtkFileChooserDialog': error occurred in libfreetype
munmap_chunk(): invalid pointer          <-- glibc abort
```

因为是原生层崩溃（不是 .NET 托管异常），`~/.cache/SourceGit/crashes/` 里没有崩溃日志，
也没有 `Native.OS.LogException` 的记录。

* gdb 抓栈（崩溃线程名 `GTK3THREAD`）：

### 2.4 符号抢占取证

* `nm -D --defined-only libSkiaSharp.so | grep -c " T FT_"` = **142**
  （`libHarfBuzzSharp.so` 为 493 个）；`strings` 显示 Skia 内嵌 **FreeType 2.13.1-motley**。
* `LD_DEBUG=bindings` 显示 **73 处** `libfreetype.so.6 → libSkiaSharp.so` 的 `FT_*` 绑定
  （系统库自绑定 19 处、Skia 自绑定 16 处）。
* 反向验证：`LD_PRELOAD=/usr/lib/loongarch64-linux-gnu/libfreetype.so.6` → Skia 在
  `FT_Palette_Select` 处 SIGSEGV（FreeType 2.12+ 把 `FT_Palette` 从 `FT_Color*` 改成了结构体）。
* Avalonia 上游源码（11.3.22，`src/Avalonia.X11/X11Window.cs`）中
  `FallbackStorageProvider` 的优先级为 **DBus portal → GtkSystemDialog（崩溃点）→ ManagedStorageProvider**；
  存在 `X11PlatformOptions.UseDBusFilePicker`，但本机**未装** `xdg-desktop-portal`。

### 2.5 一条弯路

`objcopy --localize-symbol` 对已 strip 的 `.so` 的 `.dynsym` **无效**（`T FT_` 仍为 142 个），
改绑定还需重建 `.hash/.gnu.hash`，风险过高遂放弃。

## 3. 根因

`libSkiaSharp.so`（SkiaSharp 2.88.9）静态内嵌 FreeType **2.13.1-motley**，
并以 GLOBAL 可见性导出 142 个 `FT_*`；.NET 宿主以 `RTLD_GLOBAL` 加载它，
于是这些符号抢占系统 **libfreetype.so.6（2.11.1）** —— 而 fontconfig / pango / GTK3 正是用系统那份排版。
两者 ABI 不兼容 → GTK 无法渲染文字（`drawing failure ... libfreetype`），
且 `pango_layout_set_text` 释放了损坏的堆块 → glibc `munmap_chunk(): invalid pointer` → SIGABRT。

**这不是 SourceGit 的逻辑 bug**，触发条件是任何**原生 GTK** 文件/文件夹选择器。

崩溃链路：

```
点击「打开文件夹」
  └─ TopLevel.StorageProvider.OpenFolderPickerAsync()
       └─ Avalonia.X11 → GtkSystemDialog（进程内 GTK3 文件夹选择器）
            └─ gtk_file_chooser_dialog_new() → GTK 开始排版标签文字
                 └─ pango_layout_set_text()
                      └─ fontconfig/pango 调用被抢占的 FT_*（实际是 Skia 的 2.13.1）
                           ├─ 渲染失败 → "drawing failure for widget ... libfreetype"
                           └─ 释放损坏堆块 → free() → munmap_chunk() → abort()
```

## 6. 方案取舍（详见报告第 3 节）

* **方案 A（已验证、推荐）**：不加载 GTK，改用 Avalonia 自带的托管选择器
  —— 通过 `LD_LIBRARY_PATH` 指向伪造的 `libgtk-3.so.0` 让 `dlopen` 失败即可。
* **方案 B（更正统，需 root）**：安装 `xdg-desktop-portal` + `xdg-desktop-portal-kde`，
  并在 `src/App.axaml.cs` 加 `.With(new X11PlatformOptions { UseDBusFilePicker = true })`，
  选择器在独立进程渲染；**本次未落地补丁**。
* **方案 C（治本）**：重编 SkiaSharp，用 `-fvisibility=hidden` / 版本脚本 `{ local: FT_*; }` /
  `-Wl,-Bsymbolic-functions` 避免导出 `FT_*`（objcopy 路线已证无效）。
* **方案 D（不推荐）**：`LD_PRELOAD` 一份自编译的 FreeType 2.13.1
  （fontconfig 按 2.11 ABI 编译，仍有 `FT_Palette` 风险）。

## 7. 影响范围

* 受影响：所有会打开**原生**文件/文件夹选择器的入口 —— 打开本地仓库、克隆仓库、
  添加 worktree、偏好设置里的目录选择、自定义动作、变更树里的「在文件管理器中打开」等。
* 不受影响：SourceGit 自身界面（Skia 直接用自己内嵌的 FreeType，渲染正常）。
* 与架构无关：任何「系统 FreeType < 2.13 + SkiaSharp 内嵌 2.13.1」的 Linux 发行版
  （Debian 11/12、Ubuntu 20.04/22.04 等）理论上都会复现；
  **升级系统 freetype 到 2.13+ 可从根上消除该冲突**。
