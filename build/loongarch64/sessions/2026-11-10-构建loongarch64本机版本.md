## 2. 关键难点与突破

### 2.1 上游没有 linux-loongarch64 的 .NET SDK

微软 8/9/10 全部只发布 x64 / arm64 等平台的 SDK，loongarch64 **只有运行时**：

* `dotnet-install.sh --channel 10.0 --arch loongarch64` 失败；
* nuget.org flatcontainer 对 `microsoft.netcore.app.{runtime,host}.linux-loongarch64` 返回 404。

解决办法：发现 **Loongnix 官方 NuGet 源** `https://nuget.loongnix.cn/v3/index.json`
（flatcontainer 基址 `.../v3/package/`），其中提供：

| 包 | 版本 |
| --- | --- |
| `microsoft.netcore.app.runtime.linux-loongarch64` | 10.0.14 |
| `microsoft.netcore.app.host.linux-loongarch64` | 10.0.14 |
| `microsoft.netcore.app.crossgen2.linux-loongarch64` | 10.0.14 |
| `microsoft.dotnet.ilcompiler`（NativeAOT） | **仅 9.0.2 → .NET 10 的 AOT 不可用** |

### 2.2 根因 A：`BadImageFormatException`（0x8007000B）

SDK 内 **165 个 R2R 复合镜像程序集**的 PE machine 标记是 **0xfd1d**（x64），
龙芯 CLR 拒绝加载。loongarch64 的 CLR 标记为 **0x191d**（对应 ELF e_machine 0x102）。
把 PE 头中的 machine 字段统一改写为 `0x191d` 后，CLR 回退到 IL 执行，SDK 即可原生使用。

### 2.3 根因 B：x86_64 单文件 bundle 启动器

`Roslyn/bincore/{csc,vbc,VBCSCompiler}` 与 `MSBuild` 是 **x86_64 单文件 bundle**（各 78 192 字节，
带 bundle 签名），在龙芯上会被 `latx` 模拟器接管并失败
（`Could not open '/lib64/ld-linux-x86-64.so.2'`）。
解决办法：替换为调用托管 DLL 的 shell 包装器：

```sh
export DOTNET_HOST_PATH="${DOTNET_HOST_PATH:-$ROOT/dotnet}"
exec "$DOTNET_HOST_PATH" exec "$(dirname "$0")/<csc|vbc|VBCSCompiler|MSBuild>.dll" "$@"
```

### 2.4 其它踩坑

* NuGet 源的 service index 返回 **http** 端点 → 触发 `NU1302`，需给该源加
  `allowInsecureConnections="true"`；
* 子模块自带 `depends/AvaloniaEdit/NuGet.config` 会清空包源，导致其 restore 缺少 runtime pack
  （先让主项目 restore 把包灌入全局缓存后即通过）；
* 系统只有 ICU 63/67，实测 .NET 10 接受 ICU 67；
* X11 库位于 `/usr/lib/loongarch64-linux-gnu/`。

## 6. 遗留问题 / 后续建议

* **非 AOT**：龙芯无 ILCompiler 10.x，当前是 JIT 自包含；
  建议用 `microsoft.netcore.app.crossgen2.linux-loongarch64` 10.0.14 做 ReadyToRun 预编译提速。
* **R2R 机器标记改写属 hack**：依赖 CLR 回退 IL，牺牲启动性能，升级 SDK 需重做。
* deb 依赖写死了 `libicu67 | libicu`、`libssl1.1`（Debian 12+ 只有 libssl3），建议放宽。
* 内部源 `172.17.180.18:8081`（WY.org）不可达，拖慢/报错 restore；
  上游 `build/scripts/package.linux.sh` 未扩展 loongarch64；
  AppImage 因 `appimagetool` 仅 x86_64 未做。
* deb 未实际安装（sudo 需密码、无免密）；建议在目标机执行
  `sudo dpkg -i out/sourcegit_2026.24-1_loong64.deb`。
