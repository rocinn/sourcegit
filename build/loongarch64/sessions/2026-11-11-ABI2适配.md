## 2. 如何判定 ABI 版本

```sh
readelf -h /bin/ls | grep 标志
#  标志： 0x43, DOUBLE-FLOAT, OBJ-v1     ← ABI 2.0（本机系统二进制、gcc 14 编译结果）
#  标志： 0x3,  DOUBLE-FLOAT, OBJ-v0     ← ABI 1.0（Loongnix NuGet 的 .NET 运行时）
```

* e_flags 的 `0x40` 位 = LoongArch psABI v2.0 的 **OBJ-v1** 对象 ABI 标记；
  `0x3` 只有 DOUBLE-FLOAT，是 ABI 1.0 的对象。
* Loongnix NuGet 源里 `microsoft.netcore.app.runtime.linux-loongarch64` 10.0.14
  （以及 host/apphost、SkiaSharp/HarfBuzz 原生库）全部是 **ABI1（OBJ-v0）**；
  上游没有 loongarch64 的 ABI2 二进制。

## 3. 为什么 ABI1 运行时能在本机跑

本机内置 ABI1 兼容运行库 `/usr/local/app-compat/`，并且

```sh
ls -l /lib64/ld.so.1
#  ld.so.1 -> /usr/local/app-compat/usr/lib/loongarch64-linux-gnu/ld-2.28.so
```

ABI1 二进制（我们的 apphost、libcoreclr、libSystem.Native）由这个 **旧 loader** 启动，
进程里所有原生依赖都来自 app-compat。实测 `/proc/<pid>/maps`：

* `libc-2.28.so`、`ld-2.28.so`
* `libicuuc.so.67.1` / `libicui18n.so.67.1`（.NET 的 ICU 依赖）
* `libssl`/`libcrypto` 1.1
* `libfreetype.so.6.16.1`（FreeType 2.11.1）、`libfontconfig.so.1.12.0`
* X11/Mesa/GL 全套
* 共 225 个 app-compat 映射

即：**托管层 + 原生层都在 ABI1 世界里自洽**，所以不需要为 ABI2 重编 dotnet/runtime。

## 4. 适配中实际改了什么

### 4.1 `setup-dotnet-sdk-loongarch64.sh`

* 新增第 0 步：读取 `/bin/ls` 的 e_flags，打印 ABI2(OBJ-v1)/ABI1(OBJ-v0) 判定；
* **muxer 来源改为 NuGet**：`runtime.linux-loongarch64.Microsoft.NETCore.DotNetHost` 8.0.34
  → `runtimes/linux-loongarch64/native/dotnet`（本机没有系统 dotnet；
  有 `/usr/share/dotnet/dotnet` 的旧机器仍优先用系统版）；
* SDK 载荷下载增加 `dotnetcli.blob.core.windows.net` 备用源；
* 下载缓存固定到 `WORK`（默认 `~/.cache/sourcegit-abi2/work`），可重复执行；
* 修正运行时 lib 目录：`lib/net10.0`（不是 `lib/net10.0.14`）；
* 其余保持不变：R2R 标记改写（本次 165 个）、4 个 x86_64 bundle → shell 包装器。

### 4.2 NuGet 配置（新踩的坑）

`nuget.org` 的 `SkiaSharp.NativeAssets.Linux 2.88.9` **没有 linux-loongarch64 原生库**；
第一次构建出来的 `out/linux-loongarch64` 里**没有 `libSkiaSharp.so`**，而构建过程不报错
（运行时才会炸）。用 `packageSourceMapping` 把以下包固定到 loongnix 源后解决：

```xml
<packageSource key="loongnix">
  <package pattern="SkiaSharp.NativeAssets.Linux" />
  <package pattern="HarfBuzzSharp.NativeAssets.Linux" />
  <package pattern="Microsoft.NETCore.App.Runtime.linux-loongarch64" />
  <package pattern="Microsoft.AspNetCore.App.Runtime.linux-loongarch64" />
  <package pattern="Microsoft.NETCore.App.Host.linux-loongarch64" />
  <package pattern="Microsoft.NETCore.App.Crossgen2.linux-loongarch64" />
</packageSource>
```

另外：子模块 `depends/AvaloniaEdit/NuGet.config` 会 `<clear/>` 包源，首次构建
会在子模块项目上报 `NU1101`（找不到 loongarch64 运行时包）；**先让主项目复原一次**
（灌入 `~/.nuget/packages`）再重跑即可，无需改上游代码。

### 4.3 启动器 `sourcegit-launch.sh`

* 删掉 `~/.local/bin` PATH 前置（系统 Git 2.47.2 已满足 `%(worktreepath)` 需要 2.31），
  仅保留版本自检；
* **GTK 不再无条件禁用**：本机 Avalonia 11.3 用 xdg-desktop-portal（KDE 的 Qt 对话框），
  实测打开文件夹选择器时 `/proc/<pid>/maps` 里根本没有 libgtk。
  改为：有 portal → 用原生对话框；无 portal / `SOURCEGIT_DISABLE_GTK=1` → 禁用 GTK
  走托管选择器（FreeType 2.11 与 Skia 内嵌 2.13.1 的符号冲突条件在 app-compat 里仍然存在）。
* 支持「仓库源码目录」与「deb 安装目录（脚本与二进制同目录）」两种布局。

### 4.4 `pack-deb-loongarch64.sh`

* 版本号默认读 `VERSION` 文件；
* Depends 改为本机可满足的包名：
  `libicu76 | libicu72 | libicu67`、`libssl3t64 | libssl3 | libssl1.1`、
  `libglib2.0-0t64 | libglib2.0-0`，补 `libxi6/libxext6/libxrender1/libgl1`；
* 内嵌的安装版启动脚本同步 4.3 的逻辑。
